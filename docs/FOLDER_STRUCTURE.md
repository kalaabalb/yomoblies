# Folder Structure

This repository is organized as a standard Flutter application with feature folders.

## Top-Level Layout

| Path | Purpose |
| --- | --- |
| `lib/` | Flutter application source |
| `assets/` | Local images and SVG assets used by the app |
| `android/`, `ios/`, `web/`, `linux/`, `macos/`, `windows/` | Platform runners generated by Flutter |
| `docs/` | Repository documentation |
| `.github/` | GitHub templates and workflow configuration |

## `lib/` Layout

| Path | Purpose |
| --- | --- |
| `lib/main.dart` | App entry point and provider bootstrap |
| `lib/core/data/` | Application data provider and translations |
| `lib/models/` | API-backed model classes |
| `lib/services/` | Shared network service layer |
| `lib/screen/` | Feature screens and feature-specific providers |
| `lib/shared/widgets/` | Reusable UI widgets |
| `lib/widget/` | Additional reusable widgets used by the current codebase |
| `lib/utility/` | Theme, constants, extensions, helpers, and animation wrappers |

## Feature Folders

The `lib/screen/` directory is grouped by feature:

- `login_screen/`
- `product_list_screen/`
- `product_details_screen/`
- `product_cart_screen/`
- `product_favorite_screen/`
- `product_by_category_screen/`
- `profile_screen/`
- `my_order_screen/`
- `order_details_screen/`
- `my_address_screen/`
- `tracking_screen/`

Each feature folder typically includes:

- a screen widget
- a `provider/` subfolder for state and data loading
- a `components/` subfolder for feature-specific UI pieces

## Asset Layout

| Path | Purpose |
| --- | --- |
| `assets/images/` | App logo, onboarding art, profile images, and icons |

## Documentation Layout

| Path | Purpose |
| --- | --- |
| `docs/ARCHITECTURE.md` | Architecture overview and data flow |
| `docs/API_REFERENCE.md` | REST endpoint reference used by the app |
| `docs/CONFIGURATION.md` | Runtime configuration and secret handling |
| `docs/RELEASE.md` | Release process and versioning guidance |
| `docs/screenshots/` | Placeholder area for screenshots used in the README |
